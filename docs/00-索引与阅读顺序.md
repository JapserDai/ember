# 00 · 索引与阅读顺序

## 这个文档集是什么

在写第一行代码之前，把产品想清楚。六册文档覆盖从「给谁用」到「第一张表长什么样」的完整链条。

零基础开发者最容易犯的错不是写不出代码，而是**边写边改主意**：今天想做收集系统，明天想加社交，后天觉得应该先做规划。每改一次主意，前面的代码就废掉一批。

这套文档的作用就是**把主意定死**。定死之后，改主意要走「决策记录」流程，而不是随手改。

## 阅读顺序

### 第一次读（约 40 分钟）

1. **[01-需求与定位](01-需求与定位.md)** — 先知道这东西到底为谁做、凭什么存在。
2. **[05-路线图与学习路径](05-路线图与学习路径.md)** — 知道要花多久、先做什么、要学什么。**这一册最能管理预期。**
3. **[03-技术方案](03-技术方案.md)** 的「第一步：出第一个 apk」一节 — 知道怎么最快验证工具链。

### 写代码时查

- **[02-产品规格](02-产品规格.md)** — 界面、文案、状态机、难度规则。
- **[04-数据模型与数值](04-数据模型与数值.md)** — 表结构、公式、数值表。

### 准备发布时读

- **[03-技术方案](03-技术方案.md)** 的后半部分 — 出包、落地页、版本管理。

## 术语表

这些词在文档里反复出现，先统一。

| 术语 | 含义 | 备注 |
| --- | --- | --- |
| **习惯** | 周期性重复的事，如「每天喝水」 | 三类任务之一。有连胜 |
| **待办** | 只做一次的事，如「预约体检」 | 三类任务之一。做完就消失 |
| **奖励** | 用余烬兑换的自定义奖励，如「看一集剧」 | 三类任务之一。只消耗不产出 |
| **打卡** | 完成一次记录的动作 | 全 App 的核心动作，目标 3 秒内完成 |
| **业务日** | 以 `dayStart`（默认凌晨 4 点）为界的「一天」 | 夜猫子 2 点打卡算前一天 |
| **dayStart** | 一天的切换时刻，0–23 可选 | 默认 4 点 |
| **XP** | 经验值，涨了会升级 | 只升不降 |
| **等级** | 1–50 级 | 只升不降 |
| **五维** | 体魄 / 心智 / 秩序 / 心力 / 联结 | **纯展示，不影响任何数值** |
| **余烬** | 软货币，日常打卡获得 | 用于兑换奖励、装饰、修复连胜 |
| **材料** | 硬货币，里程碑与章节获得 | 稀缺，用于高级装饰 |
| **连胜** | 连续有记录的天数 | 可断、可修、不惩罚 |
| **宽限券** | 每月自动生效的免断签次数 | 轻松 3 次 / 标准 2 次 / 硬核 0 次 |
| **修复** | 断签后 48 小时内补救连胜 | 消耗余烬 |
| **伙伴** | 名叫「小焰」的一团火 | 有状态、有台词、有记忆，**不影响数值** |
| **章节** | 用户可见的「项目」，如「把睡眠找回来」 | 替代「项目」这个冷词 |
| **路标** | 章节里的里程碑 | 三态：未到 / 进行中 / 已到达 |
| **回忆** | 自动生成或用户收藏的时间线卡片 | 非数值，只增不减 |
| **主题** | 三套外观：炉边 / 夜航 / 苔原 | 同结构，只换配色与语气 |
| **难度** | 轻松 / 标准 / 硬核 | 影响惩罚强度，默认轻松 |

## 决策记录

方案推进过程中做过的关键决定。**要改其中任何一条，先想清楚代价。**

| # | 决定 | 理由 | 影响 |
| --- | --- | --- | --- |
| D1 | 只做 Android，不做 iOS | 用户没有 iPhone；iOS 需要 $99/年、4.2 拒审、无 Mac 只能云构建 | 省下约 30% 工作量与全部苹果审核风险 |
| D2 | 不上 Google Play，走静态页 + apk 侧载 | 新个人号需 12 人×14 天封闭测试；Play 在中国大陆不可用 | 用户必须是「愿意侧载的人」，见 01 册 |
| D3 | 不装 Drizzle ORM | 只有 4–8 张表；babel/metro 配置对零基础通过率约 30%，且错误只在手机运行时暴露 | 用 expo-sqlite 原生 SQL + 手写迁移器 |
| D4 | 不装 Skia | universal apk 会增大 41MB；1.x→2.x 破坏性变更 | 用 Reanimated + react-native-svg |
| D5 | AI 改为纯本地规则引擎 | 无服务器 + 免费 + 泛用户，普通用户不会填 API Key | 全 App 零网络权限，隐私说明一句话 |
| D6 | 永不惩罚：不掉级、不没收、不死亡 | 调研明确这是 Habitica 最大差评源；断签的呈现方式本身会降低后续投入 | 所有反馈层文案都受此约束 |
| D7 | 五维属性纯展示 | 一旦影响数值，就会被刷、需要平衡、需要返工 | 不可能被刷，也不会因平衡问题返工 |
| D8 | v0.1 只做 4 张表 | 24 张表的完整设计是把工程规范误当产品需求 | 完整设计降为附录，v0.4+ 再启用 |
| D9 | 默认难度为轻松 | 与引导语「先选温和的，之后随时能改」一致 | 新用户第一印象是「不吓人」 |
| D10 | 伙伴默认名「小焰」 | 比「余烬」更亲切、更像活物 | 用户可随时改名 |

## 文档维护规则

1. **改了数值，两边都要改。** `02` 的三档难度表与 `04` 的难度表必须逐项一致。
2. **加了功能，先看 `05` 的「停车场」。** 不在当前阶段的，一律写进停车场，不写代码。
3. **改了主意，在决策记录里加一行。** 写清为什么改、代价是什么。半年后的你会需要这个。
4. **文档里不写「待补充」。** 不确定就写「暂定」并给一个默认值，不要留空。
