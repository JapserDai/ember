# 05 · 路线图与学习路径

> 本册回答：分几步走、每步多久、每步要学什么、卡住了怎么办。
> **这是最该先读的一册，因为它管理预期。**

## 0. 一页速览

### 阶段总表

| 阶段 | 版本 | 一句话目标 | 工时 | 累计 | 里程碑 |
| --- | --- | --- | --- | --- | --- |
| 0 准备 | v0.0 | 在自己的手机上跑起一个中文空壳，**并成功产出第一个 apk** | 25–45h | 25–45h | M0 |
| 1 最小闭环 | v0.1 | 每天能打卡并看到成长，数据不丢 | 80–140h | 105–185h | **M1** |
| 2 日常化 | v0.2 | 连续用 30 天不烦，断签不崩 | 70–120h | 175–305h | M2 |
| 3 目标层 | v0.3 | 让每日行动接到周/月目标上 | 70–120h | 245–425h | M3 |
| 4 收藏层 | v0.4 | 长期投入有可见的收藏与消耗出口 | 100–180h | 345–605h | M4 |
| 5 叙事层 | v0.9 | 三个月有一条可感知的主线 | 80–140h | 425–745h | M5 |
| 6 发布 | v1.0 | 别人能装、能恢复、能长期用 | **50–80h** | **475–825h** | M6 |

**总工时 475–825 小时。**

按每周 12–15 小时：约 **9–14 个月**。
按每周 10 小时：约 **12–19 个月**。

**请按 15 个月做心理预期。** 不要按「AI 几分钟生成一个页面」估工期。

### 三条纪律

1. **每个阶段结束都必须能装到自己手机上真的用。** 不能用的阶段不算完成。
2. **每个阶段有明确「不做清单」**，新想法一律进**停车场**（文末），不到对应阶段不动手。
3. **先闭环后内容，先留存后收集，先自用 30 天再给别人用。**

### 关于「跳过验证」的风险（必须知道）

原方案建议先花两周用 Notion 或纸质跑一遍这套玩法，确认自己会坚持，再写 App。

**你选择了直接开写。** 这意味着：**几百小时的风险全部押在「我会坚持用」这一个假设上。**

这不是劝阻，是让你知道赌的是什么。如果 3 个月后发现这套玩法自己都不想用，损失的是 300 小时，不是 3 周。

**降低这个风险的最低成本做法**：在阶段 1 完成后（约 3–4 个月），**强制自己连续自用 30 天**。如果做不到，停下来重新想玩法，而不是继续往上堆功能。

## 1. 阶段 0 · 环境与空壳（v0.0）

**目标**：在手机上跑起一个中文空壳，**并证明自己能产出可安装的 apk**。

### 交付物

1. `npx create-expo-app` 创建 TypeScript 项目成功
2. Expo Go 扫码能在真机打开，显示中文首页
3. **`eas build -p android --profile preview` 成功产出一个 apk，装到自己手机上**
4. Git 仓库建立，完成 3 次以上有意义的提交
5. `DECISIONS.md` 记录：SDK 版本、包名、keystore 位置、构建命令
6. keystore 已下载并离线备份

### 本阶段不做

不做数据库、不做任何业务功能、不做主题系统、不做图标与启动图。

### 验收标准

- 手机扫码能打开
- 改一行文字后热重载生效
- `git log` 能看到提交
- **手机上装着一个自己构建的 apk，能打开**
- 你能用自己的话说清「这个 App 的文件是怎么组织的」

### 工时

**25–45 小时**（大部分花在环境与报错上）

> 可行性审查建议把「出第一个 apk」当作独立里程碑。**这一步过了，剩下的都是体力活；这一步过不了，说明问题在网络或账号，早知道比晚知道好。**

### 需先学会

终端基本命令（cd/ls）、什么是 Node 与 npm、什么是 `package.json`、什么是 TypeScript 文件、什么是 React 组件、什么是 JSX、Expo 是什么、Expo Go 与 development build 的区别、Git 三个基本命令。

### 卡点预判

| 卡点 | 降级方案 |
| --- | --- |
| Windows 路径/权限/杀毒拦截 | 关掉实时防护再试；用 PowerShell 而非 cmd |
| Expo Go 与 SDK 版本不匹配 | 以官方模板为准，不手动升级 |
| 网络连不上 expo.dev | 换网络；或先用 `npx expo start --web` 本地验证 |
| EAS 构建失败 | 按 `03` §7.4 的顺序排查，**不要连续重试超过 2 次** |

## 2. 阶段 1 · 最小闭环（v0.1）

**目标**：从「打开 App」到「打卡 → 获得反馈 → 看到成长」这条链路完整跑通，且关掉 App 数据还在。

### 交付物

1. **SQLite 建库，4 张表**：`tasks`、`checkins`、`player`、`settings`（见 `04` 第一部分）
2. **任务三类型**：习惯（每天 / 每周 N 次）、待办（一次性）、奖励（用余烬兑换）。**不做负向习惯**
3. **打卡与撤销**（撤销要扣回奖励）
4. **业务日**：`localDate = "YYYY-MM-DD"` + `day_start_hour`（默认 4 点），全部走 `domain/date.ts` 一个入口
5. **XP 与等级**：`XP = ceil(60 × L^1.4)`；升级弹窗 + 轻音效
6. **五维属性**（体魄/心智/秩序/心力/联结）：每个任务绑定 1 个，打卡加属性 XP，**纯展示**
7. **连胜 + 温和断签**：断签只影响连胜数字，不扣 XP、不掉级
8. **一个静态伙伴形象位**（占位图，不解释系统）
9. **首页三块**：今日任务、今日进度、伙伴与等级
10. **设置页**：日界、难度（先只影响文案强度）、重置数据
11. **导出 JSON**（手动，写到文件并调起分享）

### 本阶段不做

推送通知、统计图表、周报、目标系统、商店、宠物收集、装备、Boss、章节、主题切换、导入、本地规则引擎、小组件、音效细节。

### 验收标准

- **连续自用 7 天**
- 每天打开 30 秒内能完成打卡
- 杀进程重开数据不丢
- 导出的 JSON 手动查看字段完整
- **断签一天后 App 没有出现任何「失败 / 惩罚 / 扣分」字样**

### 工时

**80–140 小时**

### 需先学会

React 组件的 props 与 state、`useState`/`useEffect`、列表渲染与 key、受控输入、expo-router 的文件路由、SQL 的增删改查、什么是表/主键/外键、`expo-sqlite` 的 `execSync`/`getAllSync`、异步函数与 `async/await`、JSON 序列化、`expo-file-system` 写文件、`expo-sharing` 调起分享。

### 卡点预判

| 卡点 | 降级方案 |
| --- | --- |
| SQLite 建表报错 | 先在一个 `.sql` 文件里写好，用 SQLite 命令行验证语法 |
| 日期逻辑绕晕 | **只写一个 `businessDate()` 函数，全项目唯一入口**；写 20 条单元测试锁定行为 |
| 状态管理混乱 | 先不引入 Zustand，全部用 `useState` + 重新查询；等痛点明显了再引入 |

### 关键提醒

**M1 是整个项目最重要的里程碑，不是 M6。**

M1 之后你就有了真实用户（你自己），所有后续决策都有数据支撑。

## 3. 阶段 2 · 日常化与抗挫折（v0.2）

**目标**：让「连续用 30 天」不痛苦——提醒到位、断签可救、反馈不无聊、数据可恢复。

### 交付物

1. **本地通知**：每个任务自定义提醒时间；iOS 用重复触发器（本项目不做 iOS，但概念通用）；Android 预排未来 7 天 + 启动补排 + 时区变更重排；总数控制在 20 条内
2. **通知文案库**（温和基调，20 条轮换，种子化随机保证同一天不重复）
3. **连胜修复**：断签后 48h 内可用余烬买「修复」；每月宽限（轻松 3 次 / 标准 2 次 / 硬核 0 次，静默生效并告知）
4. **打卡反馈升级**：数值飘字、进度环动画、连击里程碑（3/7/30/100 天）
5. **统计页**：近 30 天完成率、五维雷达、最佳打卡时段
6. **备份导入** + 导入前自动快照
7. **启动时补结算**（不惩罚，只补记录）
8. **主题框架落地**：结构不变只换 token，先做 2 套（炉边 + 夜航）

### 本阶段不做

目标系统、商店、收集、Boss、章节、小组件、本地规则引擎、多语言。

### 验收标准

- **连续自用 30 天**
- 故意断签 3 次：2 次被宽限、1 次手动修复成功
- 卸载重装后从 JSON 完整恢复
- 通知在 Android 上至少收到 20 次且无重复轰炸
- 统计页数字与手工核对一致

### 工时

**70–120 小时**

### 需先学会

`expo-notifications` 的权限与触发器模型、应用生命周期（前台/后台/冷启动）、时区概念、种子化 PRNG（mulberry32）、Reanimated 的基础动画 API（`useSharedValue`/`withTiming`）、JSON 校验与版本迁移。

### 卡点预判

| 卡点 | 降级方案 |
| --- | --- |
| 通知不响 / 重复轰炸 | **放弃精确闹钟**，改「打开时补发 + 每任务一条固定时间通知」，并在设置页说明 |
| Android 权限弹窗不出现 | 先建 channel 再请求权限；Android 13+ 需运行时权限 |
| Reanimated 白屏 | 检查 `react-native-worklets` 版本是否与 Reanimated 配对；用 `npx expo install` 重装 |

## 4. 阶段 3 · 目标层（v0.3）

**目标**：把每日打卡接到周/月目标上，让用户感到「我在推进某件事」，而不是「我在攒分」。

### 交付物

1. **章节**（用户可见的「项目」）：标题、为什么、期限、关联任务、进度自动计算
2. **路标**（里程碑）：三态（未到/进行中/已到达），可拖动排序
3. **周聚焦**：每周最多 3 个重点，从章节里挑，周一自动生成待确认
4. **周复盘**：周日提醒，3 个固定问题 + 1 个自由输入，5 分钟内可完成；**跳过不惩罚**
5. **月复盘**：月末最后一个周末出现，展示本月完成率、五维变化、章节进展
6. **章节收束**：完成一章生成一页回忆（封面、日期、完成的路标、写下的那句话）
7. **周报可导出为图片**

### 本阶段不做

甘特图、子目标无限层级、OKR 打分、日历拖拽排期、与他人协作。

### 验收标准

- 自用 4 周，每周复盘完成 ≥3 次
- 任一章节的进度数字可手工验算
- 周报图片能正常导出且中文不截断
- **复盘跳过 2 周后 App 无任何催促式文案**

### 工时

**70–120 小时**

### 需先学会

多对多关系与中间表、SQL 聚合（GROUP BY / COUNT）、`react-native-view-shot` 截图导出、日期区间计算（本周起止、本月起止）。

### 卡点预判

| 卡点 | 降级方案 |
| --- | --- |
| 进度口径反复改（次数？天数？权重？） | **v0.3 只支持「完成次数 / 目标次数」**，权重和自定义口径推到 v0.5 |
| 复盘表单设计过度 | 固定 3 问，不允许加字段 |

## 5. 阶段 4 · 收藏层（v0.4）

**目标**：让长期投入有可见的收藏与消耗出口，形成「打卡 → 余烬 → 买/解锁 → 收藏」的第二循环。

### 交付物

1. **伙伴系统**：1 个基础伙伴 + **12 个进化形态**，用「成长值」驱动。**不做 90 种蛋×药水组合**
2. **收藏图鉴**：伙伴、材料、回忆三类，未解锁显示剪影
3. **商店**：用余烬购买装饰、材料、一次性道具
4. **可变奖励**只用于探索与装饰：每日首次打卡后「今日发现」（种子化随机，同一天结果固定）
5. **装备系统（简版）**：只有「外观槽」（头/身/手持/背景），**纯装饰不加数值**
6. **材料合成**：3 个低级材料 → 1 个高级材料（固定配方，不做随机合成）
7. **数值防爆**：任何加成走 `diminishingReturns(bonus, max) = max × bonus / (bonus + max/2)`

### 本阶段不做

坐骑、装备属性与战斗数值、抽卡概率公示、交易、限定活动、Boss、章节。

### 验收标准

- 自用 30 天，至少完成 1 次伙伴进化
- 余烬收支在 30 天内不出现「永远花不完」或「永远买不起」
- 图鉴解锁率与打卡量正相关
- 可变奖励连续 7 天不重复同一结果，且**无法通过改系统时间刷取**

### 工时

**100–180 小时**（美术资源是大头）

### 需先学会

状态机思维（成长值 → 形态 A/B/C）、随机数与种子、资源经济的基础平衡、`react-native-svg` 绘制、图片资源管理与多分辨率。

### 卡点预判

| 卡点 | 降级方案 |
| --- | --- |
| 美术资源做不出来 | **全部用「模块化几何形象」**（身体×眼睛×配饰×配色，程序化组合），零手绘也能出 12 个形态 |
| 经济数值失衡 | 先写脚本模拟 1000 次打卡再定数值；所有加成走 `diminishingReturns` |

## 6. 阶段 5 · 叙事层（v0.9）

**目标**：给三个月的使用一条可感知的主线，让「坚持」有故事可讲。

### 交付物

1. **月度小活动**（单人）：每月 1 个主题 + 3 个目标 + 1 个装饰奖励，内容写在本地 JSON
2. **章节剧情**：**4 章**（对应四季），每章 6–8 段短文本 + 1 张插画，解锁条件是**累计打卡天数**而非连续天数
3. **单人 Boss**：每章 1 个，血量 = 本章任务完成数的映射，打卡即造成伤害；**无死亡、无失败惩罚**
4. **回忆系统**：关键节点（首次 7 天、首次进化、首次完成月目标）自动生成回忆卡
5. **内容模板化**：5 地点 × 4 情绪 × 5 属性 × 4 季节 × 3 结果，先手工填 40 条，验证结构后再扩到 200 条
6. **本地规则引擎**：温柔复盘 / 任务拆解 / 章节灵感三个功能（见 `02` §8）

### 本阶段不做

多人 Boss、世界事件、剧情分支选择、配音、动画过场。

### 验收标准

- 完整走完第 1 章（约 3 周）
- Boss 血量与打卡数据对得上
- 剧情文本不出现「你失败了」
- 回忆卡能导出图片
- **断更 2 周后回归，剧情不惩罚、只补一句「欢迎回来」**

### 工时

**80–140 小时**（写作时间另计）

### 需先学会

内容与代码分离（JSON 驱动）、章节/节点解锁的状态设计、长列表与分页渲染、中文字体加载与包体控制。

### 卡点预判

| 卡点 | 降级方案 |
| --- | --- |
| 文案写不出来或写得尬 | 先做「无剧情版」——只有月度主题 + Boss 血条；剧情以 JSON 内容包增量补，不改代码 |

## 7. 阶段 6 · 发布（v1.0）

**目标**：让别人能安装、能恢复、能长期用，且你不需要每天救火。

> **本阶段已去掉 iOS 全部工作量**（Apple 账号、TestFlight、4.2 审核、隐私清单），因此工时从 100–180h 降至 **50–80h**。

### 交付物

1. **EAS Build 出 apk**，版本号自动递增
2. **静态落地页**：介绍 + 截图 + 下载按钮 + **安装步骤说明** + 隐私说明
3. **应用图标、启动图、商店截图**（中文）
4. **三套主题全部完成**（token 化已就绪）
5. **隐私政策页**（无网络权限、数据仅存本地）
6. **首次启动引导**：90 秒内拿到第一个奖励
7. **D1–D7 引导脚本**（见 `02` §6）
8. **错误日志**（本地记录 + 用户可导出，不上传）
9. **数据迁移机制**：`user_version` 升级脚本 + 导入兼容旧版本

### 本阶段不做

小组件、多语言、云同步、社交分享、内购、Web 版。

### 验收标准

- **3 位朋友独立安装成功且无需你口头指导**
- 从 v0.1 的旧备份能导入 v1.0
- 新手引导全程 ≤90 秒拿到第一次奖励
- 连续 14 天无崩溃

### 工时

**50–80 小时**（含踩坑与反复构建）

### 需先学会

EAS Build 配置（`eas.json`）、签名证书概念（不必深入）、版本号语义、错误边界（Error Boundary）、静态站点托管。

### 卡点预判

| 卡点 | 降级方案 |
| --- | --- |
| 构建反复失败 | 按 `03` §7.4 排查；每次失败先下载日志再改 |
| 落地页不会做 | 用一个 HTML 文件 + Cloudflare Pages，不要用框架 |

## 8. 里程碑

每个节点都应该真正装到自己手机上日用。

| 里程碑 | 时点 | 你能用它做什么 | 意义 |
| --- | --- | --- | --- |
| **M0 空壳** | 阶段 0 末（~1 个月） | 打开看到中文首页，**装着自己构建的 apk** | 证明工具链通了，信心锚点 |
| **M1 自用版** | 阶段 1 末（~3–4 个月） | 每天记录 3–5 个习惯，看等级涨 | **第一次真正替代纸质打卡，开始产生真实数据** |
| **M2 稳定版** | 阶段 2 末（~5–7 个月） | 有提醒、断签能救、能备份恢复 | 可以推荐给 1–2 个朋友试用 |
| **M3 有方向版** | 阶段 3 末（~7–9 个月） | 每周定重点、周日复盘、月末看报告 | 从「打卡工具」变成「人生管理」 |
| **M4 有收藏版** | 阶段 4 末（~9–12 个月） | 攒余烬、养伙伴、解锁图鉴 | 长期留存被验证 |
| **M5 有故事版** | 阶段 5 末（~12–14 个月） | 走章节、打 Boss、收集回忆 | 产品有「完成感」 |
| **M6 可分发版** | 阶段 6 末（~14–16 个月） | 朋友自行安装 | 从自用走向他人 |

**关键提醒**

- **M1 是最重要的里程碑，不是 M6。** M1 之后你就有了真实用户（你自己）。
- 每个里程碑打 Git tag（`v0.1`、`v0.2`…），**并把当时可用的 apk 留档**（EAS 产物 30 天过期）。
- 如果某阶段超期 50%，先砍该阶段的边缘功能，保住里程碑。

## 9. 风险与回退

| 阶段 | 最可能卡住的地方 | 降级方案 |
| --- | --- | --- |
| 0 准备 | 环境装不上、EAS 连不上、Windows 特有问题 | 找一位有经验的人做 1 小时远程排障（**性价比最高的一次求助**） |
| 1 闭环 | SQLite 建表；日期逻辑绕晕 | 日期只用一个 `businessDate()`，全项目唯一入口；写 20 条单元测试 |
| 2 日常化 | 通知不响 / 重复轰炸 | 放弃精确闹钟，改「打开时补发」 |
| 3 目标层 | 进度口径反复改 | 只做「完成次数/目标次数」 |
| 4 收藏层 | 美术做不出；经济失衡 | 程序化几何形象；先跑 30 天模拟再定数值 |
| 5 叙事层 | 文案写不出 | 先做无剧情版（主题 + 血条） |
| 6 发布 | 构建失败、落地页 | 先只给自己装，分发延后 |

### 通用回退原则

1. **每个阶段只允许一个「新技术风险点」。** 同时引入两个没学过的东西，卡住时无法判断是谁的问题。
2. **先写能跑的丑版本，再美化。**
3. **每次大改前打 tag。** 零基础最常犯的错是「改坏了回不去」。
4. **卡住超过 4 小时就换方案。** 把问题记进 `docs/blockers.md`，隔天再看往往有答案。
5. **AI 生成的代码必须能解释每一行。** 解释不了就要求逐行注释，否则不要合并。

### 如果做不下去，体面收场

| 降级 | 说明 |
| --- | --- |
| 1. 只保留 Android + 侧载 | 已经是当前方案 |
| 2. 砍动画 | 只留淡入淡出和触感 |
| 3. 砍通知 | 改「打开即用 + 每日补签」 |
| 4. 砍章节与伙伴成长 | 只保留打卡 + 等级 + 五维 |
| 5. 停更但继续自用 | **完全体面的结局**。一个只服务自己的 apk 是成功 |
| 6. 彻底放弃 | **先把数据导出成 JSON** |

## 10. 学习路径

### 10.1 必须学（按顺序）

| # | 内容 | 学到什么程度 | 阶段 |
| --- | --- | --- | --- |
| 1 | 终端与文件系统 | 会用 cd/ls/mkdir，知道当前目录 | 0 |
| 2 | Git 三件套 | add / commit / log / 回退到某个 commit | 0 |
| 3 | JavaScript 基础 | 变量、函数、数组、对象、`map/filter`、`async/await`、`try/catch` | 0–1 |
| 4 | TypeScript 类型 | 会读类型报错，会写 interface 和联合类型 | 1 |
| 5 | React 核心 | 组件、props、state、`useState`、`useEffect`、列表渲染、条件渲染 | 1 |
| 6 | React Native 布局 | Flexbox、`View/Text/Pressable/ScrollView/FlatList`、StyleSheet | 1 |
| 7 | expo-router | 文件即路由、`_layout`、动态路由、导航跳转 | 1 |
| 8 | SQL 基础 | 增删改查、WHERE、ORDER BY、GROUP BY | 1–3 |
| 9 | 数据建模 | 主键、外键、一对多、迁移概念 | 1–3 |
| 10 | 日期与时区 | 本地日期 vs UTC、`dayStart`、夏令时概念 | 1 |
| 11 | 异步与生命周期 | Promise、AppState、冷启动/后台/前台 | 2 |
| 12 | 动画基础 | Reanimated 的 shared value 与 `withTiming` | 2 |
| 13 | 状态管理 | Zustand（只学这一个，不要都学） | 3 |
| 14 | 构建与发布 | EAS Build、签名、版本号 | 6 |

### 10.2 明确**不需要**学

| 不需要 | 理由 |
| --- | --- |
| 后端 / 服务器 / 数据库运维 | 本项目纯本地，没有 API、没有登录、没有云 |
| Docker / Kubernetes / CI-CD 深入 | EAS 已托管构建 |
| Redux / GraphQL / 微服务 / 设计模式大全 | 过度设计，只会拖慢进度 |
| 原生 Android（Kotlin） | 除非做小组件，否则完全不需要 |
| Webpack / Babel 配置 | Expo 已封装，**不要碰** |
| 算法与数据结构竞赛内容 | 会写循环和数组操作足够 |
| Jest / Detox 全套 | 只需会写几个纯函数测试锁定日期与数值逻辑 |
| Figma 深入 | 会用基础形状和配色即可，主题靠 token 不靠设计稿 |
| 多语言 / i18n | 只做中文，硬编码即可（但集中到 `strings.ts` 方便改文案） |
| iOS / Swift / Xcode | 明确不做 iOS |
| Drizzle / Prisma 等 ORM | 只有 4 张表，手写 SQL 更直接 |

### 10.3 学习方式

- **不要先学完再动手。** 每个阶段「学 30% → 做 → 卡住 → 补 30%」，比通读教程有效 3 倍。
- **每个概念都要能用自己的话讲一遍。** 讲不出就是没懂。
- **AI 用于解释代码，不用于跳过理解。** 让 AI「逐行解释这段代码在做什么、为什么这么写」，比让它「再写一个功能」更有价值。
- **每周留 2 小时读自己的代码**，尝试不看注释说出每个文件的作用。
- **AI 生成的代码，解释不了就不要合并。**

## 13. 对照 Habitica：永远不做的功能

| Habitica 功能 | 决定 | 理由 |
| --- | --- | --- |
| Party（组队） | **永远不做** | 需要服务器；社交压力与「自我关怀」基调冲突 |
| Guild（公会） | **永远不做** | 同上，且内容审核成本无法承担 |
| Challenge（挑战赛） | **永远不做** | 依赖社区；排行榜会制造比较焦虑 |
| World Boss | **永远不做** | 需要全局状态同步 |
| 宝石 / 订阅 / 内购 | **永远不做** | 硬约束：免费、无商业化 |
| 账号系统 / 云同步 | **永远不做** | 硬约束：无账号、无服务器 |
| 好友 / 私信 | **永远不做** | 无社交、无 moderation 能力 |
| 公开排行榜 / PvP | **永远不做** | 与「不比较、只关怀」直接冲突 |
| 职业系统 | **不做，改为五维** | 职业引入技能、法力、战斗数值，复杂度爆炸 |
| 带数值的装备 | **不做，只做装饰** | 数值平衡对单人开发者是黑洞 |
| 蛋 × 药水 90 种组合 | **不做，改为 12 形态进化** | 组合爆炸但体验同质 |
| 死亡 / 掉级 / 没收资产 | **永远不做** | 调研明确：Habitica 最大差评源 |
| 负向习惯（扣分按钮） | **永远不做** | 等于让用户每天主动扣自己分 |
| 多语言 | **不做** | 硬约束：仅中文 |

**参考边界**：Habitica 为 GPL-3.0 且 2026-08 起禁止 AI 生成代码贡献。本项目**只参考机制的数学形式**（如 `0.9747^value` 衰减、`diminishingReturns`），所有代码独立实现，不复制源码、文案、数据结构命名。
