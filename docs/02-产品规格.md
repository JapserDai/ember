# 02 · 产品规格

> 本册描述「长什么样、怎么交互、说什么话」。写界面和文案时查这里。
> 数值规则与 `04` 必须逐项一致。

## 0. 六条不可违背的原则

1. 不死亡、不掉级、不没收资产、不做公开比较。
2. 任何一次记录不超过 3 秒、不超过 2 次点击。
3. 五维属性只展示，不影响任何数值。
4. 每个数字都能解释：为什么加、为什么减、离下一档还差多少。
5. 不联网也完整可用（本 App 根本不申请网络权限）。
6. 中文原生文案，不用翻译腔，不堆感叹号。

## 1. 四套主题

### 1.1 设计原则

四套主题是四种「被对待的方式」，不是四个配色变体。组件结构、间距节奏、信息层级完全一致，只替换颜色、圆角、阴影、字体与语气。

**所有组件只读 token，不写死颜色。** 这是硬性代码规范：任何界面里出现 `#B23A17` 这样的字面值，都是 bug。

| 主题 | 一句话气质 | 适用场景 | 主色印象 |
| --- | --- | --- | --- |
| **炉边 furnace** | 傍晚回到家，有人替你把炉火拨亮 | 低能量、夜晚、需要被接住 | 灰烬底 + 余烬红 |
| **夜航 nightvoyage** | 深夜驾驶舱，仪表微亮，只有你和方向 | 深夜专注、独处、需要秩序 | 深海蓝 |
| **苔原 tundra** | 白天的窗边书桌，纸、铅笔和一杯水 | 白天、工作学习、轻量规划 | 苔藓绿 |
| **晨光 daybreak** | 清早，窗子刚打开，空气是干的 | 早起、想清醒一点的时候 | 冷白底 + 深青 |

前三套各有亮暗两版；**晨光只有亮版**，这是它的设计主张，不是没做完（见 §1.5）。

### 1.2 炉边 furnace

色板不是「暖色调」的泛称，是炉膛里四样东西的实际颜色：**灰烬、烟炱、余烬、炭火**。
房间是冷的（背景是冷中性灰），火是暖的（主色偏红、火心偏橙）。
这是全 App 唯一允许「发光」的主题，别处一律安静。

| Token | Light | Dark | 是什么 |
| --- | --- | --- | --- |
| primary 主色 | `#B23A17` | `#E4633A` | 余烬。唯一的高饱和暖色，对比度 4.9:1 |
| secondary 辅色 | `#6B6862` | `#8E8A83` | 炉渣。未点着的炭、次要小字 |
| background 背景 | `#EAE8E3` | `#17161A` | 灰烬。房间的冷中性，几乎无彩 |
| surface 表面 | `#F6F4EF` | `#211F25` | 纸。底栏与输入框，只比背景亮一档 |
| text 文字 | `#201D1B` | `#EDE7DF` | 烟炱。带一点红底的黑，不是纯黑 |
| accent 强调 | `#D97B2B` | `#F2A24F` | 炭火。**只用于非文字元素**（火心、光晕、圆点） |
| success 成功 | `#4E6B45` | `#8FB57C` | |
| warning 警告 | `#8F5314` | `#E0A85A` | |
| danger 危险 | `#A02F26` | `#D9717C` | |

派生：`textMuted` = text 68%（亮）/ 64%（暗），对比度仍 ≥ 4.5:1；`border` = text 12%（亮）/ 14%（暗）；`rule` = text 24%（亮）/ 22%（暗），用于区块分隔；`onPrimary` = `#F6F4EF`（亮）/ `#17161A`（暗）；`highlight` = accent 向白混合 55%（亮）/ 35%（暗），用于火心；`primaryDeep` = primary 向 text 混合 30%（亮）/ 向 background 混合 40%（暗），用于火焰的侧舌——亮色往深、暗色往沉，两个方向都是「更弱的那股火」。

**为什么不用奶油底 + 陶土橙**：那是「温暖」这个词的默认答案，任何温暖调性的产品都会自动生成它。而陶土是陶器的颜色——哑光、土气、不发光。余烬不是。

形状与节奏：圆角 20（卡片）/ 14（按钮、输入框）/ 999（胶囊）；阴影 `0 8 24 rgba(32,29,27,0.12)`，只在确实需要「浮起来」的少量地方用；间距基数 4，页面左右 20，卡片内边距 16，卡片间距 12。整体偏松软，允许大留白。

字体：标题用霞鹜文楷 LXGW WenKai（OFL-1.1），正文用思源黑体 Source Han Sans SC（OFL-1.1），字重 400/600；字号 28/22/17/15/13。字体按常用字集子集化打包，缺字回退系统字体。**阶段 1 尚未打包字体，先用系统字体**，层级只靠字号与字重。

语气：短句、具体、像熟人；可以有停顿和口语；少用感叹号；不说教。

### 1.5 晨光 daybreak —— 只有亮色的第四套主题

前三套都是「傍晚 / 深夜 / 白天窗边」的时间场景。**晨光是唯一一套不做暗色的主题**：它的整个主张就是「现在就是亮的」，跟着系统变暗反而破坏了它。

色板走**青灰 + 墨绿**，不碰奶油色、不碰陶土色（D11 已把那条路否决）。底色是冷调的近白，主色是深青，强调色是一点偏黄的日照。

| Token | 值 | 是什么 |
| --- | --- | --- |
| primary 主色 | `#245A5A` | 深青。对比度 7.2:1 on bg，白字压在上面 7.8:1 |
| secondary 辅色 | `#5E6B68` | 雾灰绿。次要小字，5.1:1 |
| background 背景 | `#F4F6F7` | 清晨的空气。冷调近白，不是奶油色 |
| surface 表面 | `#FFFFFF` | 纯白。底栏与输入框 |
| text 文字 | `#171C1B` | 墨。15.9:1 |
| accent 强调 | `#C08A3E` | 日出。**只用于非文字元素**（2.8:1，达不到正文标准） |
| success 成功 | `#3F6B45` | |
| warning 警告 | `#8A5A12` | |
| danger 危险 | `#9B2F28` | |

派生：`textMuted` = text 68%（5.7:1）；`border` = text 12%；`rule` = text 24%；`onPrimary` = `#FFFFFF`；`highlight` = accent 向白混合 55% → `#E3CAA8`；`primaryDeep` = primary 向 text 混合 30% → `#204747`。

**形状与节奏**：圆角 16 / 12 / 999；不用阴影，用 1px `border` 分隔（和苔原同一路，但间距更松）；页面左右 22，卡片内边距 16。**层级**字重只用 400 / 600 两档，比另外三套少一个中间档；medium（500）只出现在交互状态里（未完成的标题比已完成的重一档），四套主题都有这一档。

**字体**：标题与正文都用思源黑体，字号 27/21/17/15/13。

**语气**：清早的、干爽的。不用感叹号，不用「新的一天」这类口号；说事实，不说愿景。

**只有亮色意味着什么**（要在实现里显式处理，不能悄悄回退）：

- 选晨光时，`theme_mode` 里的 `dark` 与 `system`（系统为深色时）都会被解析为亮色。
- 主题选择页上，晨光这一项**不显示深浅切换**，并写一句「这套只有亮的」。
- 代价：夜里用这套主题会刺眼。这是它的取舍，不试图修复。

### 1.6 同一句话，四种说法

场景：断签一天后打开 App。

| 主题 | 提示语 |
| --- | --- |
| 炉边 | 昨天炉子凉了一点，不碍事。现在添一根柴，火就回来了。 |
| 夜航 | 昨天没有记录。数据还在，连胜进入可修复状态，剩余 47 小时。 |
| 苔原 | 昨天空了一天。习惯不会因为一天就消失，今天想从哪一件小事重新开始？ |
| 晨光 | 昨天没有记录。今天还是这个时候，坐下来就好。 |

### 1.7 主题切换的数据层

`settings` 表的三个字段：

| 字段 | 类型 | 默认 | 取值 |
| --- | --- | --- | --- |
| `theme_id` | TEXT | `furnace` | `furnace` / `nightvoyage` / `tundra` / `daybreak` |
| `theme_mode` | TEXT | `system` | `light` / `dark` / `system` |
| `reduce_motion` | INTEGER | 0 | 0 / 1 |

切换只写这三个字段，走内存态并立即持久化，不触发任何业务数据变更。主题与难度、备份完全解耦。

**跟随系统深色**：炉边 / 夜航 / 苔原三套都有 Light/Dark 两套色板。`theme_mode = system` 时读取系统配色；夜航在系统模式下优先暗色（暗色是它的设计主场），炉边和苔原优先亮色，用户可手动覆盖。系统切换时用 200ms 颜色过渡，不整页重载。**晨光没有暗色板**，解析规则见 §1.5。

## 2. 可选惩罚难度

### 2.1 三档具体规则

| 维度 | **轻松（默认，界面标注「温和」）** | 标准 | 硬核 |
| --- | --- | --- | --- |
| 收益倍率 | ×0.85 | ×1.00 | ×1.20 |
| 每月自动宽限 | **3 次** | 2 次 | **0 次** |
| 连胜修复成本 | 15 余烬 | 40 余烬 + 1 材料 | 100 余烬 + 3 材料 |
| 修复后效果 | 连胜原样保留 | 连胜保留，但当日 XP 减 30% | 连胜保留（需付费修复） |
| 断签扣余烬 | **0%（不扣）** | 5%，单日上限 30 | 10%，单日上限 80 |
| 补记窗口 | 72 小时 | 48 小时 | 24 小时 |
| 补记收益 | 100% | 70% | 40% |

**三档共同底线**：不死亡、不掉等级、不没收已获得资产、不清空历史、不减少属性上限、不影响已解锁内容。

> 断签扣减只在**修复期结束仍未修复**时执行。修复成功则不扣。

### 2.2 默认档位与中途切换

- **默认轻松**。首次引导第 3 屏一句话说明：「先选温和的，之后随时能改。」
- 随时可切换，入口在「我的 → 设置 → 节奏 → 难度」。切换立即生效，只影响切换之后的业务日。
- **历史处理**：已有连胜保留；已扣的余烬不返还；已生成的回忆不改写；统计页标注「X 月 X 日起使用 XX 难度」。
- **禁止切换的时机**：处于 `repairable`（可修复）状态时禁止修改难度，防止「断签后切轻松」套利。
- 硬核切回其他档：需二次确认，当前契约可选择「完成」或「提前结束」；提前结束不扣任何东西，只在回忆里留一条「某契约提前结束」。

### 2.3 硬核契约

入口：难度页「签订契约」，仅在硬核档可用。

**流程**

1. 选一个核心习惯（只能选一个，且必须是每日型）。
2. 选时长：14 天或 30 天。
3. 写一句「为什么」（20–60 字，必填）。
4. 押注余烬：100 / 200 / 400 三档，只能押已有余烬，不借款、不预支。
5. 签下名字（输入你的名字确认，默认「旅人」），生成契约卡。

**规则**

- 每天完成该习惯即打卡；漏一天，契约失败。
- 失败时押注余烬**不消失**，自动兑换成一件「灰烬纪念物」放进回忆（有外观、有日期、有那句为什么），并附一句「这次到这里，押注变成了纪念。」
- 成功完成：押注全额返还，额外奖励 1.5 倍，并获得一件限定纪念物，放进回忆。
- 契约期间不能删除该习惯；可暂停契约（最多 3 天，不消耗天数），暂停不视为失败。
- 同时只能有 1 份契约。

> 设计要点：即使最硬的档位，**押注也不会真的消失**，只是变成纪念物。这是「永不没收资产」原则的体现。

### 2.4 绝不出现的文案（禁用词表）

「永不惩罚」不能靠写文案时自觉，得靠一张表兜底。任何动态生成的文案（复盘、事件、通知、引导）在显示前都过一遍 `src/domain/text-rules.ts`，命中就换一条，**不做抠词**——抠词会留下语义破碎的句子。

| 类别 | 词 | 为什么禁 |
| --- | --- | --- |
| 失败类 | 失败、前功尽弃、差一点、太可惜 | 把一次记录说成不可挽回的结果 |
| 惩罚类 | 惩罚、归零 | 暗示会有代价，与三档难度「不没收」冲突 |
| 命令类 | 必须、应该、不准偷懒 | 剥夺选择权 |
| 羞辱类 | 你让、失望、受伤、饿死 | 情感勒索 |
| 比较类 | 排行榜、别人已经 | 制造攀比 |

**代码里的词表与这张表必须逐字一致。** 加词先改这里，再改 `FORBIDDEN_WORDS`。

## 3. 任务与目标（用户视角）

### 3.1 创建任务的最小表单

**必填只有 1 项**：名称（占位「比如：睡前读 10 页」）。其余全部有默认值。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| 类型 | 每天 | 可切「每周 N 次」「只做一次」 |
| 属性 | 秩序 | 系统按关键词猜：读/学→心智，跑/睡→体魄，整理→秩序，冥想/情绪→心力，联系朋友→联结；可改 |
| 图标与颜色 | 自动 | 从 12 个图标里选，可换 |
| 提醒 | 关 | 开启后默认 20:00 |

**高级选项默认折叠**（点「更多」展开）：难度（轻/中/重，影响 XP）、目标次数、开始日期、可补记窗口、子步骤（最多 5 个）、标签、关联目标、备注。

**首次创建不展示任何高级项。**

### 3.2 目标

目标是一句话，不是一张计划表。没有子目标、没有阶段、没有百分比。

**创建目标只有三个字段**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 一句话目标 | 是 | 占位「比如：把睡眠找回来」，最多 80 字 |
| 截止日 | 否 | 不填就是不限期，界面不显示倒计时，也不因过期变红 |
| 关联任务 | 否 | 从已有任务里挑，一个任务最多属于一个目标 |

**进度**

- 进度 = 关联任务里已完成的数量 / 总数，显示成「3 / 5 件」。
- 不显示百分比，不显示进度环。完成一件，数字加一。
- **一个目标可以不挂任何任务**：那就只显示那句话和截止日，没有进度行。目标本身仍然成立。
- 关联任务里「已完成」的判定跟今天页一致：习惯看今天是否打卡，待办看是否勾掉。目标是回顾用的，不会因为今天没打卡就判负。

**完成**

- 可以手动标记完成，入口在目标详情右上角。
- 关联任务全部完成时，系统在目标卡片上提示一句「关联的事都做完了。这个目标算完成了吗？」由用户点确认，系统不自动关掉它。
- 已标记完成的目标保留在列表里，不删除、不清空，只是折叠起来。

**列表**

- 按「进行中 / 已完成」两组排列，已完成的组默认折叠，标题右侧显示条数。

## 4. 页面与信息架构

### 4.1 底部导航（4 个）

**今天 / 目标 / 回忆 / 我的**

| Tab | 职责 |
| --- | --- |
| 今天 | 记录与当日 |
| 目标 | 一句话目标与进度 |
| 回忆 | 时间线、周报、月报、纪念物 |
| 我的 | 只放个人数据：等级、XP、五维、连胜、称号。设置是单独一页，从这里进入 |

### 4.2 首页首屏（3 秒完成一次记录）

**结构是账本，不是卡片墙。** 通栏的行、极淡的分隔线、没有阴影也没有圆角容器。
页面上没有插画、没有角色，唯一带颜色的是点着的那排炭；其余全部安静。

自上而下：

1. **日期 + 问候 + 一行状态**：日期小、字距 1.5、灰色；问候大、左对齐；再下一行小字「Lv.7 · 今天 2 / 5」。三行，不在一行里挤。状态行只读，不可点。
2. **今日进度条（炭排）**：一排小横条，每完成一件点着一块，没点着的留灰。不显示百分比，不做圆环。
3. **「今天」习惯区**：通栏的习惯行：左侧圆点 + 名称 + 连胜小字。单击 = 完成，长按 = 部分完成或跳过菜单。
4. **今日待办**：最多 3 条，方框 + 标题，右滑延期。
5. **底部一条「今天还可以」**：推荐一个 1 分钟微行动，上方一条细线隔开。

**完成的视觉处理**：不划删除线。划线是行政语言，带着「这件事过去了」的评判。
完成的行**退到灰里**——文字降对比、字重降一档、圆点点着。扫一眼，还在等你的那几行自己亮着，做完的自己沉下去。

**进度不用圆环**：圆环是仪表盘的语言，属于「你在被测量」的场景。这个 App 要的是「炉膛里有几块炭点着了」，所以是一排小横条。也不显示百分比——未完成时显示 0% 会像在扣分。

**记录路径：解锁 → 点一下习惯 = 完成。总计 1 次点击，无需进入任何页面。**

### 4.3 各页关键交互

**今天**

- 下拉出现「补记昨天」（仅难度允许时）。
- 习惯按钮左侧小圆点表示今日状态；完成时圆点填充并轻微放大。
- 顶部那一排炭随完成数点亮，点着的那一块有个短暂的亮起。
- 全部做完时问候语换成「今天到这儿了。」，不推荐新任务。

**目标**

- 列表按「进行中 / 已完成」分组，已完成的折叠成一行。
- 每一条的排版顺序是「那句话 → 为什么 → 进度」，先让你想起为什么，再看走到哪儿了。
- 进度显示「3 / 5 件」，不显示百分比；没挂任务时显示「还没挂任务」。
- 点进去可以改标题、改为什么、设截止日、把任务挂上来。
- 没有子目标、没有阶段、没有纵向路径图。

**回忆**

- 时间线倒序，卡片式：日期、事件类型、缩略插画、一句话。
- 周报卡：本周记录数、最稳的习惯、最常出现的时段、一句总结。
- 月报卡：本月完成率、五维变化、目标进展。
- 顶部筛选：全部 / 周报 / 月报 / 纪念物。

**我的**

- 这一页只放个人数据：头像、名字、等级、经验条、余烬、五维属性条。
- 五维只画条和数字，不给建议、不做评分。
- **设置不在这页里**，单独一页，从页头右上角进入。理由：「我的」是「你走到了哪儿」，设置是「把 App 调成你想要的样子」，两件事混在一页会让前者被后者的条目压掉。

**头像**

头像**不是上传的图片**，是按玩家 ID 生成的一块炭。理由：上传要相册权限、要裁剪、要在备份里带二进制，三条都和「完全离线、无权限」的底线打架。生成图案零依赖、零权限，导出时只多带一个整数。

- 图案是围绕圆心取 5–8 个半径不等、整体略带压扁的顶点连成的闭合折线，内部再连一到两条短棱。轮廓填 text 色 15% 的淡影，棱与轮廓用 text 色描边，中心附近一枚 accent 色的实心圆当火心。颜色全部读 token，四套主题下自动正确。
- **为什么不是星星或对称图形**：对称图案转多少度都像同一个，十几个排在一起会读成同一个头像的变体。不规则多边形没有对称轴，每块炭都是单独一块。
- 火心的大小由图案自带的 `warmth`（20–89）决定，位置离中心有一小段偏移——固定在中点时，所有人的头像正中都有同一个点，图案的差异反而被盖住。
- 名字与头像同一行；「换一个」在等级那一行的右侧、紧挨着等级（**靠左，不是整行右对齐**）——右对齐会正好落在「设置」下面，同一列两个可点元素容易点错。**不做「点头像换一个」**：那会让人以为能换头像本身（拍照、选图），而这里只换一个图案。
- 生成是确定性的：`(player.id, player.avatar_seed)` 决定图案。所以杀进程重开、导入数据、换设备，头像都不变。
- 实现：`src/domain/avatar.ts`（纯函数，产出轮廓点、棱、火心位置）+ `src/components/PlayerAvatar.tsx`（react-native-svg，颜色全部读 token）。重掷只把 `player.avatar_seed` +1 并写库，图案本身永远不存。

**设置**

- 独立页面，从「我的」页头右上角进入，返回后回到「我的」。
- 三组：外观（主题、深浅、动效）、节奏（难度、日界、提醒）、数据（备份、导入）。
- **行的状态分三种，判断标准是「这个值现在存不存在」，不是「能不能改」**：
  - `readonly`：库里有真实值、此刻正在生效，只是还没有修改入口。显示真实值。
  - `later`：功能还没做，没有值可显示。右侧写「之后」，**不给点击**——点了没反应比不给点更让人困惑。
  - `interactive`：能点。按下整行降透明度。
- 阶段 1 里 `interactive` 只有一项（主题），`readonly` 有四项（深浅、动效、难度、日界），`later` 有三项（提醒、备份、导入）。不把「能不能改」当唯一标准，否则同一页一半显示真值、一半写「之后」，会让人以为显示真值的那几行能点。
- **主题选择页**（点「主题」进入，`app/settings/theme.tsx`）：四套主题竖排，每套显示名称、一句话气质、一块当前配色的小样（三个色块：background / primary / accent）。选中项左侧有一条 primary 竖线，不用对勾图标。选晨光时**不显示深浅切换**，那一行换成一句「这套只有亮的」（见 §1.5）——判断依据是 `theme.supportsDark`，不是页面里写死主题 id。
- **不做「清空全部数据」这一行**，直到它真的能用。一个不能用的删库入口比不写更糟：用户会以为 App 有这个能力，而它什么也不做。
- 「数据」组下面写一句「备份还没做。在那之前，卸载会丢掉全部记录。」——这不是文案润色，是把原来那句「卸载之前记得先导出一份」的假承诺收回。
- 页底放隐私说明。难度页有对比表与当前档位标记；备份页有导出 JSON、导入、最近一次备份时间、导入前自动快照提示。

## 6. 内容模板系统

### 6.1 一条探索事件模板的 JSON 结构

```json
{
  "id": "evt_lighthouse_dusk_001",
  "version": 1,
  "type": "explore",
  "slots": {
    "location": "lighthouse",
    "mood": ["quiet", "tired"],
    "attribute": "mind",
    "season": ["autumn", "winter"],
    "outcome": ["small_gain", "insight"]
  },
  "title": "{地点}的{时段}",
  "body": "{开场}你在{地点}停下。{细节}。{收束}",
  "fragments": {
    "开场": ["风把门吹得轻响。", "灯还没亮。"],
    "细节": ["桌上有一本翻到一半的书", "窗外的海是铅灰色"],
    "收束": ["你坐了一会儿，什么也没做。", "你记下一句话，然后合上本子。"]
  },
  "rewards": { "xp": 12, "ember": 3, "attribute": { "mind": 1 } },
  "weight": 8,
  "cooldownDays": 14,
  "requires": { "minLevel": 2 },
  "excludes": ["evt_lighthouse_dusk_002"],
  "tags": ["solitude", "night", "no_dialogue"]
}
```

**字段说明**

- `slots`：五个维度（地点 5 × 情绪 4 × 属性 5 × 季节 4 × 结果 3），用于检索与组合，不直接拼进正文。
- `fragments`：真正用于渲染的句段库，按语义槽分组，每组 2–4 条。
- `rewards`：固定区间，按难度微调，**不允许随机大额**。
- `excludes`：互斥 id，避免同一晚出现两个「灯塔」。
- `tags`：供兼容性规则使用。

### 6.2 槽位与变体的组织方式

- 组合不是字符串随机拼接，而是「模板骨架 + 语义槽位」。每个槽位有 grammar 标记（名词/动词短语/形容词），只允许同标记互换。
- **兼容规则三层**：
  1. 语义互斥：tags 冲突（如 `indoor` 与 `outdoor`）不共存。
  2. 情绪匹配：事件 mood 必须包含用户当日心情，或为空（通用）。
  3. 句式去重：同一模板 14 天内只用一次；同一 fragments 组内的句子，7 天内不重复。
- **生成流程**：筛选候选 → 按 weight 加权 → 种子 PRNG（`playerId + localDate + eventId`）抽取 → 组装 → 二次校验（长度 40–120 字、无禁用词、无重复句）→ 失败则回退到通用池。
- **安全**：所有 fragments 预先人工审校；上线前跑一遍禁用词表（与 §2.4 同一份）。

## 7. 本地规则引擎（原「AI 辅助」）

### 7.1 定位

**不联网、不需要 API Key、不申请网络权限。**

原方案考虑过接入 AI，但三个约束同时成立时它不可行：无服务器（只能让用户自己填 Key）+ 免费（不能代付）+ 面向普通用户（他们不会去申请 Key）。

所以改为**本地规则引擎**：用模板、关键词匹配和统计规则，产出「像人写的」结果。效果上限低于真 AI，但对「不联网也完整可用」这条硬约束是唯一自洽的解法。

**不标注「AI 生成」**，因为它本来就不是。界面上直接叫功能名。

### 7.2 提供的两个功能

| 功能 | 输入 | 输出 | 本地实现 |
| --- | --- | --- | --- |
| **温柔复盘** | 最近 7 天记录 | 120 字以内总结：一个模式、一件值得保留的小事、一个下周可尝试的微调 | 24 条总结模板 × 12 个变量槽位（完成率区间、最稳习惯、最常时段、断签次数、属性分布…），按记录数/完成率/时段选模板 |
| **任务拆解** | 一件拖着没做的事 | 3 个可在 15 分钟内完成的第一步 | 动词库（准备/联系/打开/写下/清理/预约）× 任务名关键词匹配；识别失败时给通用兜底：「先花 2 分钟，把这件事需要的东西列出来」 |

### 7.3 明确不做

- 聊天伴侣、闲聊、情感陪伴对话
- 心理诊断、情绪分析结论
- 自动创建大量任务、自动修改数值
- 读取通讯录 / 相册 / 健康数据 / 位置
- 任何形式的网络请求

### 7.4 隐私说明（原文，放在设置页页底）

**阶段 1 用的版本**（备份与导出还没做，所以不提）：

> 这个 App 没有网络权限。没有账号，没有服务器，数据只在这台手机上。

**导出与删除上线后换成完整版**：

> Ember 没有任何网络权限。你的记录只存在这台手机上，不会发送到任何地方。这里没有任何 AI 服务，所有「复盘」「拆解」都是用内置模板生成的。你可以随时导出全部数据，也可以一键删除全部数据。

**「没有网络权限」必须在配置里坐实，不能只写在文案里。** Expo 的 Android manifest 模板默认带 `INTERNET`、`SYSTEM_ALERT_WINDOW`、`VIBRATE` 和读写外部存储权限（`@expo/config-plugins` 的 `withAndroidBaseMods.js`）。所以 `app.json` 的 `android.blockedPermissions` 必须显式移除 `INTERNET` 与 `ACCESS_NETWORK_STATE`——否则这句话就是假的，用户装完在系统设置里能查到联网权限。

## 8. 空状态与边界情况

零基础开发者最容易忽略、但用户最先撞上的地方。

| 场景 | 表现 |
| --- | --- |
| 首次打开，还没有任何任务 | 显示引导第 2 屏的模板卡片，**不是空白列表** |
| 今天所有习惯都完成了 | 问候换成「今天到这儿了。」，不推荐新任务 |
| 今天一个任务都没有 | 「今天空着。要不要放一件小事进来？」+ 3 个快捷模板 |
| 目标一个任务都没挂 | 显示「还没挂任务」，不显示「0 / 0」 |
| 目标的关联任务全做完了 | 顶部提示「这件事都做完了。要收起来吗？」——用户自己决定，不自动关闭 |
| 连胜为 0（从未开始） | 不显示连胜数字，显示「第一天」 |
| 断签后 | 显示「历史最佳 X 天 / 累计 Y 天」，**不显示「归零」** |
| 一个目标都没有 | 「还没有目标。可以先在「今天」记几天，看看自己真正在意哪件事。」 |
| 连续 30 天没打开 | 打开时先给「回归小结」recap，不是直接进首页 |

## 9. 无障碍与细节

| 项 | 要求 |
| --- | --- |
| 触控目标 | 最小 44×44 |
| 对比度 | 正文文字对比度 ≥ 4.5:1（四套主题的色板已按此校验） |
