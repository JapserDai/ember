# 02 · 产品规格

> 本册描述「长什么样、怎么交互、说什么话」。写界面和文案时查这里。
> 数值规则与 `04` 必须逐项一致。

## 0. 六条不可违背的原则

1. 不死亡、不掉级、不没收资产、不做公开比较。
2. 任何一次记录不超过 3 秒、不超过 2 次点击。
3. 五维属性只展示，不影响任何数值。
4. 每个数字都能解释：为什么加、为什么减、离下一档还差多少。
5. 不联网也完整可用（本 App 根本不申请网络权限）。
6. 中文原生文案，不用翻译腔，不堆感叹号。

## 1. 主题（v0.1 只有一套）

### 1.1 设计原则

**v0.1 只有一套白底主题。** 这是有意的取舍，不是没做完。

早先规划过四套（炉边 / 夜航 / 苔原 / 晨光），各自有一套语气与配色。它们的价值在于「好看」和「被对待的方式」，但代价是：每加一个界面都要在四套配色下各看一遍，每加一个颜色 token 都要在四套里各定一次值。在一个还没有备份、没有提醒、没有回忆页的 App 里，好看不是当下最缺的东西（见 D27）。

所以这一版先把主题收成最基础的一层：**白底、深灰字、一个蓝色主色**。等功能补齐，再把其余主题加回来——那时 token 的形状已经稳了，加一套只是多写一次 `buildPalette` 调用。

**所有组件只读 token，不写死颜色。** 这是硬性代码规范：任何界面里出现 `#2564CF` 这样的字面值，都是 bug。

### 1.2 白（唯一的主题）—— Fluent 语汇

这一套照 **Microsoft To Do** 的视觉语汇定（D29）。「像」不等于「白底 + 蓝按钮」，
真正像的是三件事：

1. **底是极淡的暖灰**（`#FAF9F8`），不是纯白。纯白会让每张卡片都得靠描边才浮得起来；
   Fluent 的卡片是靠「白纸压在灰底上」分开的。
2. **层级全靠中性灰四档**（`#323130` / `#605E5C` / `#A19F9D` / `#EDEBE9`），
   主色只出现在「可点」「选中」「正在发生」三件事上。
3. **圆角小（4）、阴影极轻**。Fluent 的卡片是纸片，不是气泡。大圆角是另一种语言。

| Token | 值 | 是什么 | 对比度（卡片白底） |
| --- | --- | --- | --- |
| primary 主色 | `#2564CF` | To Do 的蓝。只表示「可以点 / 已选中」 | 5.5:1 |
| secondary 辅色 | `#605E5C` | Fluent neutralSecondary。次要文字、未选中的描边 | 6.5:1 |
| background 背景 | `#FAF9F8` | Fluent neutralLighter。极淡的暖灰 | — |
| surface 表面 | `#FFFFFF` | 卡片、底栏、输入框 | — |
| text 文字 | `#323130` | Fluent neutralPrimary。不是纯黑 | 13.0:1 |
| accent 强调 | `#0078D4` | Fluent 主题蓝。**只用于非文字元素** | 4.5:1 |
| success 成功 | `#107C10` | | 5.4:1 |
| warning 警告 | `#8A5300` | | 6.3:1 |
| danger 危险 | `#A4262C` | 过期、删除确认 | 7.3:1 |

派生：`textMuted` = text 68%（4.7:1 —— **0.62 只有 3.99:1，实测过，不能用**）；
`border` = text 12%（`#E6E6E6`）；`rule` = text 20%（`#D6D6D6`）；
`onPrimary` = `#FFFFFF`；`highlight` = accent 向白混 50% → `#80BCEA`；
`primaryDeep` = primary 向 text 混 28% → `#2E3F5D`。

**形状与节奏**：圆角 **4**（卡片 / 按钮 / 输入框同一档）；页面左右留白 **16**，
卡片之间留 **2px 的缝**（缝里露出页面底色，这是 Fluent 分组的方式）；
阴影 `0 1 3 rgba(0,0,0,0.06)`，elevation 1。

**字体**：阶段 1 尚未打包字体，先用系统字体（Windows 上是 Segoe UI，Android 落到 Roboto）。
字号 **24 / 20 / 15 / 14 / 12**，行高 32 / 26 / 21 / 20 / 16。

**不做的事**：不用拉开字距的小字标签（`letterSpacing`）——那是「模板感」最重的一处记号，
To Do 的小字只是颜色淡一点。层级靠字号与颜色，不靠字距。

### 1.3 没有的东西（明确不做）

| 能力 | 现状 | 为什么 |
| --- | --- | --- |
| 多套主题 | 已删除 | 先做功能，主题最后做（D27） |
| 深浅切换 / 跟随系统深色 | 已删除 | 只有一套亮色板，没有可切换的东西 |
| 主题选择页 `/settings/theme` | 已删除 | 只有一个选项的列表是占位符，不是选择 |

`settings` 表仍然保留 `theme_id` 与 `theme_mode` 两列（建表 SQL 已发布，按 D31 不改动已发布的常量），但界面不再读写它们。种子数据照常写入默认值。将来主题回来时，这两个字段直接可用。

### 1.4 主题切换的数据层（留给将来）

主题回来时按这张表接：

| 字段 | 类型 | 默认 | 取值 |
| --- | --- | --- | --- |
| `theme_id` | TEXT | `furnace` | 见 `src/db/schema.ts` 的 `ThemeId` |
| `theme_mode` | TEXT | `system` | `light` / `dark` / `system` |
| `reduce_motion` | INTEGER | 0 | 0 / 1 |

切换只写这三个字段，走内存态并立即持久化，不触发任何业务数据变更。主题与难度、备份完全解耦。

**新增主题时**：`ThemeId` 加取值 → 写一条扩 CHECK 的迁移（重建 settings 表，只有 1 行，成本可忽略）→ 在 `theme/tokens.ts` 加一套 `buildPalette` → 恢复 `ThemeProvider` 的 `themeId` 状态与主题选择页。**不要**改已发布的建表 SQL。

## 2. 可选惩罚难度

### 2.1 三档具体规则

| 维度 | **轻松（默认，界面标注「温和」）** | 标准 | 硬核 |
| --- | --- | --- | --- |
| 收益倍率 | ×0.85 | ×1.00 | ×1.20 |
| 每月自动宽限 | **3 次** | 2 次 | **0 次** |
| 连胜修复成本 | 15 余烬 | 40 余烬 + 1 材料 | 100 余烬 + 3 材料 |
| 修复后效果 | 连胜原样保留 | 连胜保留，但当日 XP 减 30% | 连胜保留（需付费修复） |
| 断签扣余烬 | **0%（不扣）** | 5%，单日上限 30 | 10%，单日上限 80 |
| 补记窗口 | 72 小时 | 48 小时 | 24 小时 |
| 补记收益 | 100% | 70% | 40% |

**三档共同底线**：不死亡、不掉等级、不没收已获得资产、不清空历史、不减少属性上限、不影响已解锁内容。

> 断签扣减只在**修复期结束仍未修复**时执行。修复成功则不扣。

### 2.2 默认档位与中途切换

- **默认轻松**。首次引导第 3 屏一句话说明：「先选温和的，之后随时能改。」
- 随时可切换，入口在「我的 → 设置 → 节奏 → 难度」。切换立即生效，只影响切换之后的业务日。
- **历史处理**：已有连胜保留；已扣的余烬不返还；已生成的回忆不改写；统计页标注「X 月 X 日起使用 XX 难度」。
- **禁止切换的时机**：处于 `repairable`（可修复）状态时禁止修改难度，防止「断签后切轻松」套利。
- 硬核切回其他档：需二次确认，当前契约可选择「完成」或「提前结束」；提前结束不扣任何东西，只在回忆里留一条「某契约提前结束」。

### 2.3 硬核契约

入口：难度页「签订契约」，仅在硬核档可用。

**流程**

1. 选一个核心习惯（只能选一个，且必须是每日型）。
2. 选时长：14 天或 30 天。
3. 写一句「为什么」（20–60 字，必填）。
4. 押注余烬：100 / 200 / 400 三档，只能押已有余烬，不借款、不预支。
5. 签下名字（输入你的名字确认，默认「旅人」），生成契约卡。

**规则**

- 每天完成该习惯即打卡；漏一天，契约失败。
- 失败时押注余烬**不消失**，自动兑换成一件「灰烬纪念物」放进回忆（有外观、有日期、有那句为什么），并附一句「这次到这里，押注变成了纪念。」
- 成功完成：押注全额返还，额外奖励 1.5 倍，并获得一件限定纪念物，放进回忆。
- 契约期间不能删除该习惯；可暂停契约（最多 3 天，不消耗天数），暂停不视为失败。
- 同时只能有 1 份契约。

> 设计要点：即使最硬的档位，**押注也不会真的消失**，只是变成纪念物。这是「永不没收资产」原则的体现。

### 2.4 绝不出现的文案（禁用词表）

「永不惩罚」不能靠写文案时自觉，得靠一张表兜底。任何动态生成的文案（复盘、事件、通知、引导）在显示前都过一遍 `src/domain/text-rules.ts`，命中就换一条，**不做抠词**——抠词会留下语义破碎的句子。

| 类别 | 词 | 为什么禁 |
| --- | --- | --- |
| 失败类 | 失败、前功尽弃、差一点、太可惜 | 把一次记录说成不可挽回的结果 |
| 惩罚类 | 惩罚、归零 | 暗示会有代价，与三档难度「不没收」冲突 |
| 命令类 | 必须、应该、不准偷懒 | 剥夺选择权 |
| 羞辱类 | 你让、失望、受伤、饿死 | 情感勒索 |
| 比较类 | 排行榜、别人已经 | 制造攀比 |

**代码里的词表与这张表必须逐字一致。** 加词先改这里，再改 `FORBIDDEN_WORDS`。

## 3. 任务与目标（用户视角）

### 3.1 创建任务的最小表单

**必填只有 1 项**：名称（占位「比如：睡前读 10 页」）。其余全部有默认值。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| 类型 | 每天 | **v0.1 只有「每天」与「只做一次」两档**；「每周 N 次」必须带目标次数，属高级项，v0.2 再开放 |
| 属性 | 秩序 | 系统按关键词猜：读/学→心智，跑/睡→体魄，整理→秩序，冥想/情绪→心力，联系朋友→联结。**v0.1 只显示猜测结果，不给选**——五维纯展示，不影响数值，不值得为它加一个选择器 |
| 图标与颜色 | 自动 | v0.1 不做，用统一的圆点 |
| 提醒 | 关 | **不在这一页**：提醒要停下来想「我几点做这件事」，与「必填只有名字」冲突。所有提醒集中在「设置 → 节奏 → 提醒」里设（D36） |

**高级选项默认折叠**（点「更多」展开）：难度（轻/中/重，影响 XP）、目标次数、开始日期、可补记窗口、子步骤（最多 5 个）、标签、关联目标、备注。

**首次创建不展示任何高级项。**

### 3.2 目标

目标是一句话，不是一张计划表。没有子目标、没有阶段、没有百分比。

**创建目标只有三个字段**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 一句话目标 | 是 | 占位「比如：把睡眠找回来」，最多 80 字 |
| 为什么 | 否 | 占位「三个月后回来看，你最想读到哪句话？」，最多 200 字；详情页可改 |
| 截止日 | 否 | 不填就是不限期，界面不显示倒计时，也不因过期变红；给「一周后 / 一个月后 / 三个月后」三个快捷项，也可手写 `YYYY-MM-DD` |

关联任务不在新建页问，写目标时还不知道要挂什么；它在详情页里勾选，勾上即生效。

**进度**

- 进度 = 关联任务里已完成的数量 / 总数，显示成「3 / 5 件」。
- 不显示百分比，不显示进度环。完成一件，数字加一。
- **一个目标可以不挂任何任务**：那就只显示那句话和截止日，没有进度行。目标本身仍然成立。
- 关联任务里「已完成」的判定跟今天页一致：习惯看今天是否打卡，待办看是否勾掉。目标是回顾用的，不会因为今天没打卡就判负。

**完成**

- 可以手动标记完成，入口在**目标详情页最下面**（不是右上角）：这一页的主要动作是「把目标写清楚」，
  一个常驻在页头的「完成」按钮会让误触变成一次要解释的撤销；放在最下面，要先滚过自己写的那句话才够得着。
- 关联任务全部完成时，系统在目标卡片上提示一句「关联的事都做完了。这个目标算完成了吗？」由用户点确认，系统不自动关掉它。
- 已标记完成的目标保留在列表里，不删除、不清空，只是折叠起来。

**列表**

- 按「进行中 / 已完成」两组排列，已完成的组默认折叠，标题右侧显示条数。
- 进行中组按截止日排：有截止日的在前，近的在上；没有截止日的排后面，按创建时间。
- 没有逾期红色，没有「还剩 X 天」的倒计时。

**语气示例**

| 写法 | 说明 |
| --- | --- |
| 把睡眠找回来 | 一句话说清方向，不写指标 |
| 搬家前把东西理一遍 | 有截止日、有场景，不做拆解也能开始 |
| 今年多和家里人说说话 | 不需要关联任务，挂着也算数 |

首次引导让用户从下列模板中选 1–3 个，**不出现空白画布**。

**习惯模板（8 个）**

## 4. 页面与信息架构

### 4.1 底部导航（4 个）

**今天 / 目标 / 回忆 / 我的**

| Tab | 图标 | 职责 |
| --- | --- | --- |
| 今天 | 火苗 | 记录与当日 |
| 目标 | 旗子 | 一句话目标与进度 |
| 回忆 | 叠放的两张卡片 | 时间线、周报、月报、纪念物 |
| 我的 | 人像（圆头 + 肩线） | 只放个人数据：等级、XP、五维、连胜、称号。设置是单独一页，从这里进入 |

**图标是手绘 SVG（`src/components/TabBarIcon.tsx`），不装图标库。** 理由与代价：

- 图标库为了四个图标要带上整套字形映射表；而且通用图标库是几何工业风（精确圆角、统一 2px、占满画框），混进这个「墨与纸」的界面，底栏会像从别的 App 里贴过来的。
- **「目标」不用靶心。** 靶心是「你正在被打分」的语言，与「不评判」的底线冲突——和 §4.2 否掉进度环是同一个理由。改成旗子：「到这面旗为止」，有方向、没有分数。
- **「回忆」不用时钟。** 时钟是圆的，而这一页里「时间」是排在卡片上的属性，不是页面主角；一个圆形时钟会让它看起来像设置里的计时器。这一页本身就是卡片式时间线，所以直接画卡片。
- **「今天」是火苗**，四个图标里唯一直接指向产品本体的一个，所以给它最中央的位置；内弯的一笔是火舌，没有它，水滴和火苗在 23px 下分不出来。
- **「我的」是人像**，刻意和 `PlayerAvatar` 的生成人像同一个骨架（头 + 脖子 + 肩膀）——点进去看到的那张脸和图标是同一件事。
- **不用汉字当图标**（早先的做法是 今 / 标 / 忆 / 我）：汉字和下方的标签是同一种东西，「今」压着「今天」读起来是重复，而不是「图形 + 名字」；19px 的字和 11px 的标签字重接近，视觉上分不出哪层是图标。
- 画法约定：viewBox 24×24、只描边不填充、圆头圆角、**path 只用绝对命令**（M / L / C / Q / Z）。和 `avatar.ts` 同一个理由——要能在没有 React 的环境里打成点阵验形（`scripts/preview-tab-icons.ts`）。
- **选中态三件事同时变，任何一件单独失效都还能分辨**：线宽 1.45 → 1.95（不看颜色也认得出来，色盲用户靠这一条）、颜色 次要色 → 正文色、图标下方一个 3px 的余烬点。颜色不用主色：主色是「火」的颜色，四个图标里已经有一个是火，底栏全都染上余烬红会把火的分量用光。
- 代价：四个图标是手写的，加第五个 tab 时要自己画并跑一次预览脚本；线宽是两档而不是连续插值，切换时没有过渡动画。

### 4.2 首页首屏（3 秒完成一次记录）

**结构是账本，不是卡片墙。** 通栏的行、极淡的分隔线、没有阴影也没有圆角容器。
页面上没有插画、没有角色，唯一带颜色的是点着的那排炭；其余全部安静。

自上而下：

1. **日期 + 问候 + 一行状态**：日期小、字距 1.5、灰色；问候大、左对齐；再下一行小字「Lv.7 · 今天 2 / 5」。三行，不在一行里挤。状态行只读，不可点。
2. **炉膛（一条正在烧起来的火带）**：全宽一条，左端是炉膛的火，做完一件火头往右推一截，全做完整条烧满。不显示百分比，不做圆环，不做刻度。
3. **「今天」习惯区**：通栏的习惯行：左侧圆点 + 名称 + 连胜小字。单击 = 完成，长按 = 部分完成或跳过菜单。
4. **今日待办**：最多 3 条，**每条一张白卡片**（Fluent 的纸片，不是通栏行）。
   卡片里是：圆形勾选框 + 标题 + 一行元信息（截止日 · 备注 · 归属目标）。
   **整张卡片不可点，只有圆圈可点**——在 To Do 里，手指落在圈上是「完成它」，
   落在文字上是「打开它」，而这一页没有「打开」的去处。
   长按整行撤销（圈太小，长按它是「按住不放」，手感不对）。
   卡片之间留 2px 的缝，缝里露出页面底色。
5. **底部一条「今天还可以」**：推荐一个 1 分钟微行动，上方一条细线隔开。
6. **右下角一个圆形「+」**（56px，主色填充，白色加号，SVG 画的）。
   不随滚动移动——不管列表多长，「加一件」永远在同一个位置。
   编辑态下隐藏：那一屏是「清理」，不是「添加」。

**完成的视觉处理分两类**（D29 收窄了 D13）：

- **习惯**：不划删除线。划线是行政语言，带着「这件事过去了」的评判——而习惯是
  「今天做过了，明天还要做」。完成的习惯**退到灰里**：文字降对比、字重降一档、圈填满。
- **待办**：**划删除线**。待办本来就是「做完就结束」，划线在这一类里是**准确**的，
  不是评判。Microsoft To Do 也是这么做的。

**进度不用圆环，也不用静态的炭排**：圆环是仪表盘的语言，属于「你在被测量」的场景。但早先那排「七个小横条、点着一块填一块」也只解决了其中一半——它只能表达 `3 / 7` 这个**比例**，而比例是数字的图形化，不是动力。

现在画的是一件事**正在发生**：火从炉膛往右烧出去。左端永远有一小簇火（哪怕一件都没做），火头是一团更亮的光，做完一件它就往右推一截。它表达的不是「你完成了多少」，而是「火还在烧，而且还在往前走」。

这和「不评判」不冲突，因为：没有百分比、没有「还差 3 件」、没有刻度；**一件都没做时不是空的**——左端那簇火是「炉子还在这儿」，与「今天有几件事」无关。

**火头用 `primaryDeep`，不是 `highlight`**：`highlight` 是 accent 向白色混合得到的，在白底上压在同为浅色的背景上对比度只有 1.4–1.8，几乎不存在。白纸上「深 = 热」，所以火头取 primary 往文字色混的那一档（`#224F9B`）。早先还有暗色主题时这里分两支（暗色用 `highlight`、亮色用 `primaryDeep`），现在只剩白底，直接取深的那一支。

**记录路径：解锁 → 点一下习惯 = 完成。总计 1 次点击，无需进入任何页面。**

**点完必须看得到发生了什么。** 早先点一下之后，界面上唯一的变化是圆点变色、数字 +1——两件事都太安静，用户做了事却像是没发生，于是下一次就没有理由再点。这不是审美问题，是反馈缺失。

所以记录成功后，进度条右侧那一格（平时显示等级）会换成**刚刚真的发生了什么**：`+26 XP · +3 余烬`，升级时换成 `升级了 · +30 XP`。3 秒后自己退回等级。

三条边界：
- **借用同一格，不另起一行**：另起一行会让下面的内容整体下移，而「刚点的那一行」正好在视线里——内容一动，眼睛就跟丢了。
- **只报已发生的事**（+26 XP），不写「做得不错」「继续保持」——那是评价，而且是在替用户判断这件事值不值。
- **不弹窗、不撒花**：弹窗会打断（用户可能想连着记三件），撒花是庆祝，而庆祝意味着「这件事值得被表扬」。

**未完成的行要有「可以点」的样子。** 早先的圆点 10px、空心细边、用次要色，在视觉上几乎不存在——用户扫过列表时看到的是五行字，而不是五个可以点的东西。现在改成 18px 空心圈（1.6 边宽，用正文色），尺寸接近正文字高，成为这一行除标题外唯一有重量的东西，也就是**这一行的把手**。按下时圈会轻轻收一下（0.82），告诉手指「按到了」。

### 4.3 各页关键交互

**今天**

- 下拉出现「补记昨天」（仅难度允许时）。
- 习惯按钮左侧小圆点表示今日状态；完成时圆点填充并轻微放大。
- 顶部那一排炭随完成数点亮，点着的那一块有个短暂的亮起。
- 全部做完时问候语换成「今天到这儿了。」，不推荐新任务。
- **长按已记录的行 = 撤销这一次。** 先弹一句确认「撤销这一次？这一次的奖励会一起退回。」，
  确认后 XP、余烬、属性、连胜一起回到打卡前。不撤销已经结算过的日子。
- 已完成的待办**当天仍留在列表里**（不再出现「做完就消失」），否则撤销入口就没有了；
  第二天它自然不再出现。
- 一个任务都没有时，显示「今天空着。要不要放一件小事进来？」+ 3 个快捷模板（§3.3）。
  点模板**一次点击就建好**并立刻可以打卡，旁边另给「自己写一件」进新建页。
  有内容时，区块标题右侧出现「加一件」。

**目标**

- 列表按「进行中 / 已完成」分组，已完成的折叠成一行，标题右侧显示条数。
- 每一条的排版顺序是「那句话 → 为什么 → 进度」，先让你想起为什么，再看走到哪儿了。
- 进度显示「3 / 5 件」，不显示百分比；没挂任务时显示「还没挂任务」。
- 关联的事都做完了而目标还没被标记完成时，那一行多一句询问，**系统不自动关掉它**。
- 点进去可以改标题、改为什么、设截止日、把任务挂上来、手动标记完成。
- 详情页的文字改动按「存下来」落库（挂任务是勾选即时生效），没存的改动在离开时问一句。
- 可挂的任务只列「还没挂任何目标的」和「已经挂在这个目标上的」；
  一个任务只属于一个目标，属于别的目标的不列出来（列出来也选不了，只会让人多点一次）。
- 没有目标时显示一句具体的例子 + 一个「写一句」，不显示空白输入框。
- 没有子目标、没有阶段、没有纵向路径图。

**回忆**

- 时间线倒序，卡片式：日期、事件类型、缩略插画、一句话。
- 周报卡：本周记录数、最稳的习惯、最常出现的时段、一句总结。
- 月报卡：本月完成率、五维变化、目标进展。
- 顶部筛选：全部 / 周报 / 月报 / 纪念物。

**我的**

- 这一页只放个人数据：头像、名字、那句自我介绍、等级、经验条、余烬、五维属性条。
- 五维只画条和数字，不给建议、不做评分。
- **设置不在这页里**，单独一页，从页头右上角进入。理由：「我的」是「你走到了哪儿」，设置是「把 App 调成你想要的样子」，两件事混在一页会让前者被后者的条目压掉。
- **这一页没有任何编辑入口。** 头像与名字都是纯展示，不可点；改它们去「设置 → 资料」。早先头像是换头像的入口、名字是资料页的入口——代价是用户点头像或名字时，并不知道自己正在离开这一页。
- 自我介绍**没写时整块不出现**，不留一行「还没写」的占位——那一行会变成待办，而这一页不是待办清单。

**人物资料（头像、名字、一句自我介绍）**

全部在「设置 → 资料」组里：

| 行 | 去哪 | 改什么 |
| --- | --- | --- |
| 头像 | 底部面板（就地） | 左右走挑一只像素动物，点「用这一只」落库 |
| 名字 | `app/profile/edit.tsx` | 名字与那句自我介绍。点「保存」才写库 |
| 一句自我介绍 | `app/profile/edit.tsx` | 同上（同一张表单） |

**为什么名字与自我介绍是同一页、两个入口**：它们是同一份资料，同一张表单里保存。做成两个页面会让人以为它们分别保存。两行都给入口而不是只留一行，是因为设置页的每一行都应该能直接点到它管的东西——只有「名字」能点时，用户会以为自我介绍改不了。

**为什么表单只有两行也要单独一页**：名字是整个 App 里最常被别处引用的字段（页头、以后的回忆叙述、导出文件）。就地编辑会让设置页在编辑状态下多出一个键盘和一个保存按钮，把下面三组挤下去。

**为什么头像不进这张表单**：换头像是点开面板左右走两步就定下来的事；搬进表单会变成「改完名字滚下去换头像再回来保存」，把一个可以就地完成的事拖成一个批量动作。

**规则**（`src/domain/profile.ts`，纯函数）：

| 项 | 规则 | 理由 |
| --- | --- | --- |
| 名字长度 | 最多 16 个字，按**码点**数而不是 `str.length` | 一个 emoji 在 JS 里是 2 个码元、在用户眼里是 1 个字。用户数的是字，不是码元 |
| 名字规范化 | 去首尾空白，内部连续空白压成一个空格 | 名字会出现在页头、备份文件、回忆叙述里，带三个空格会在这些地方各自排版成不同样子 |
| 自我介绍 | 最多 80 字，**允许为空** | 「不写」本身是一种表达 |
| 自我介绍规范化 | 去首尾空白与行尾空白，连续空行压成一个，**保留分段** | 它是一小段话，用户可能想分段 |
| 禁用词 | 两者都过一遍全 App 的禁用词表 | 用户在自己写的字段里写「必须」「失败」，会被别的页面读成 App 在对用户说那句话 |
| 其余一律放行 | 写「躺平」「摆烂」「我最近很糟」都存 | 自我描述不是 KPI。App 只拦物理上放不下的和底线词，不评价用户写了什么 |

**保存策略：只有点「保存」才写库，不做失焦即保存。** 中文输入法下候选词还没选完就失焦很常见，失焦即保存会把半个拼音写进库。代价是用户可能改了却忘了点保存，所以**返回时如果还有未保存的改动会问一句**（比较的是去空白后的值——多打一个空格不该被判成有改动，那种确认框最后一定会被条件反射按掉）。

**头像**

头像有**七个手绘的像素动物**，用户左右走挑一个：狐狸 / 猫 / 兔子 / 熊猫 / 青蛙 / 企鹅 / 猫头鹰。选中哪一只只存一个词（`player.avatar_id`），长相本身是代码里的常量。

上一版是「按玩家 ID 生成半身墨色人像 + 可从相册上传照片」，这一版整体换掉了。换掉的理由不是它不好看，是它**不是一个可选项**：

- 生成的东西没有「挑」这件事。用户没法说「我想要猫」，只能一直点「换一个」直到碰上一张顺眼的——而「顺眼」没法验证，只能靠运气。
- 生成的东西没有「收藏」的价值。这一版要的是「可供用户左右选择」，那就必须是**有名有姓的少数几个**，而不是无穷多的随机组合。
- 上传照片那条路要三个原生包、要按 SDK 版本做能力探测、要在备份里背一张 base64 照片。它服务的需求（用自己挑的图）现在被「挑一只动物」覆盖了，而代价一点都不小。
- 人像的几何很重：几十条贝塞尔、脸型与发型的相互作用、脖子与下颌的过渡，每改一笔都要重新验形。像素图一笔就是一个方块，改一格就看到一格。

**画的是 16×16 的像素图，不是插画。** 头像最大显示 64px，16×16 每格 4px；缩到 32px 也还是清清楚楚的方块。挑选面板里会同时摆出七个小图，它们必须能在一排里被分辨出来——像素图靠**轮廓**就分得开，不靠颜色。

- **只用五种材质，不用写实颜色**：墨（轮廓、眼睛）、毛（身体）、浅（脸与肚皮）、点（眼睛高光）、强调（嘴与喙）。材质到颜色的映射只有一处（`roleColor`），颜色全部读主题 token——换主题时头像自动跟着走，不需要改七张图。「狐狸是橙色」这种写实期待被刻意放弃：这个 App 里没有一张写实的东西，七只动物统一用「墨 + 两档灰 + 一个强调色」，像一本印章画册。
- **七只是按剪影差异选的**，不是按可爱程度：狐狸（尖耳 + 收窄的下巴）、猫（尖耳小脸 + 两点胡须）、兔子（五行高的长耳）、熊猫（圆耳 + 黑眼圈）、青蛙（眼睛长在头顶）、企鹅（白肚皮黑背）、猫头鹰（大眼 + 三角喙）。排在一起靠剪影就能分开，色盲用户拿到的信息一样。
- **顺序是一条线，不是随机排**：从「最野的」走到「最圆的」。狐狸排第一是因为它剪影最锐利，而默认值是最多人不会去改的那一个。
- **眼睛必须是墨色**：眼睛是这张图的锚点。任何一只动物看不清眼睛，在 32px 下就只剩一团灰。
- **每只只留一处强调色**：嘴、喙、鼻子选一个。两处会让视线来回跳。
- **左右对称**：第 n 格与第 15-n 格必须相同，手画时只写左半边再镜像。`scripts/preview-avatar.ts` 会检查这一条，以及行数、列数、有没有眼睛。
- 相邻同色块**合并成一个宽矩形**再画：每只动物从 ~200 个方块降到 ~60 个。一屏里可能有十来个头像（面板 7 个小图 + 1 个大图 + 「我的」页 1 个），不合并就是两千多个 SVG 节点。
- 头像**不带底色**：它坐在卡片的白底上，而「点」角色恰好也是卡片白——眼睛高光会「漏」进背景里。这是有意的：那一处白点读起来是「眼里的光」，不是「一个白方块」。
- 实现：`src/domain/avatar.ts`（纯数据：七个网格 + 角色到颜色的映射）+ `src/components/PlayerAvatar.tsx`（react-native-svg，一个原生视图内部画若干 `<Rect>`）。`scripts/preview-avatar.ts` 把七个网格打成 ASCII 点阵并检查对称性，改图之后先跑它，再上模拟器。

**点「头像」= 打开挑选面板**

入口在「设置 → 资料 → 头像」。点开是一个**底部面板**，不是新页面：换头像是一眼就能决定的事，跳页再返回对它来说太重了。

面板里三样东西：

| 元素 | 做什么 |
| --- | --- |
| 中间的大图（96px）+ 左右两个箭头 | 左右走。走到头回绕（狐狸的前一个是猫头鹰） |
| 下面一行七个小图（32px） | 只回答「一共有几只、我现在在哪一只」。点一下也能跳过去，那是给已经知道自己要哪一只的人用的近路 |
| 「用这一只」 | 落库。滑动不落库 |

**为什么是「左右走」而不是一个网格。** 网格（七个小图排成两三行，点一个）看起来更直接，但它把选择变成了**比较**：七个小图同时在场，人会横着扫、找「哪个更好看」，而「更好看」没有答案。一次只看一只、左右走，是**浏览**：看到一只觉得可以就停下。这与「不比较、不评分」的底线是同一件事。

**为什么滑动不落库。** 滑动只是看，落库要有一次明确的确认。否则每滑过一只都会写一次库，而用户最后停在哪一只只取决于他松手的位置——那不是一个「选择」。缩略图那一行选中态用一条下划线，不换底色：换底色会让它读起来像「一个被选中的按钮」，而这一行只是位置指示器。

**读屏**：大图传 `accessible`，由 `describeAvatar` 读成「狐狸，尖耳朵，收窄的下巴」。滑动之后读屏会念新的那一句，视障用户靠这句话知道换到了哪一只；三个按钮与七个缩略图各有自己的 `accessibilityLabel`（缩略图带「第 n 只，狐狸，尖耳朵，收窄的下巴」）。

**设置**

- 独立页面，从「我的」页头右上角进入，返回后回到「我的」。
- 四组：**资料**（头像、名字、一句自我介绍）、外观（动效）、节奏（难度、日界、提醒）、数据（备份与导入）。
- **行的状态分三种，判断标准是「这个值现在存不存在」，不是「能不能改」**：
  - `readonly`：库里有真实值、此刻正在生效，只是还没有修改入口。显示真实值。
  - `later`：功能还没做，没有值可显示。右侧写「之后」，**不给点击**——点了没反应比不给点更让人困惑。
  - `interactive`：能点。按下整行降透明度。
- 当前 `interactive` 有四项（头像、名字、一句自我介绍、提醒），`readonly` 有三项（动效、难度、日界），`later` 已清空（备份与导入都已实现）。不把「能不能改」当唯一标准，否则同一页一半显示真值、一半写「之后」，会让人以为显示真值的那几行能点。
- **「提醒」这一行点进去是一页，不是一个开关**：开关只能表达「开/关」，而提醒必须回答「哪件事、几点」。列表里每件事一行，各自选时刻（`app/settings/reminders.tsx`）。
  - 每一行给四个快捷选项（不提醒 / 08:00 / 12:00 / 20:00）+「写时间」（收 `20:30` 这种格式，不收「晚上八点半」）。与截止日那一栏同一套交互。
  - **权限在用户第一次打开某条提醒时才请求**，不在启动时弹。一打开 App 就问「允不允许发通知」，用户还不知道要提醒什么，大概率拒绝；而 Android 上拒绝过就不再弹了。
  - 权限被拒时那一页顶部说清去哪儿打开（「设置 → 应用 → Ember → 通知」），**不隐藏**下面的开关——隐藏了用户会以为这个功能坏了。
  - 通知文案 20 条轮换，按「任务 + 日期」定种子：同一天重排多少次都是同一句，第二天换一句。只描述事实或发出邀请（「今天这一格还空着」「有空的时候，记一下」），不催促、不提数字、逐条过禁用词表。
  - **通知无声、不弹横幅、不带角标**，只出现在通知栏。声音与横幅是催促的形态，与文案说的不是同一件事。
  - 一天最多排 20 条，超出时按最近优先截断；预排 7 天，启动补排。
- **「资料」组是「我的」页让出来的那一部分**：头像、名字、那句自我介绍原先挂在「我的」页上（点头像换头像、点名字改资料）。挪进设置的理由——它们都是「把 App 调成你想要的样子」，与主题、难度同类；而「我的」页回答的是「你走到了哪儿」。混在一起的代价是：用户点头像或名字时，并不知道自己正在离开那一页。
  - 「头像」右侧显示当前那一只的名字（`狐狸` / `猫` / …），点击弹底部面板（不跳页——换头像是一眼决定的事）。
  - 「名字」与「一句自我介绍」进同一张表单（`app/profile/edit.tsx`），因为它们是同一份资料。
  - 自我介绍没写时右侧显示「还没写」而不是空白：空白看起来像这一行坏了。
- **「外观」组只剩「动效」一行。** 原先是「主题 / 深浅 / 动效」三行：「深浅」是一行 `readonly`（显示真值但点不动），一行永远点不动的设置比没有更让人困惑，先删了；「主题」这次也删了，因为主题选择页里只剩一套配色——一个只有一项的单选列表不是选择，是占位符。**多套主题与主题选择页等阶段 4 再回来**（D27，恢复路径见 §1.4）。
- **不做「清空全部数据」这一行**，直到它真的能用。一个不能用的删库入口比不写更糟：用户会以为 App 有这个能力，而它什么也不做。
- 「数据」组下面写一句「备份还没做。在那之前，卸载会丢掉全部记录。」——这不是文案润色，是把原来那句「卸载之前记得先导出一份」的假承诺收回。
- 页底放隐私说明。难度页有对比表与当前档位标记；备份页有导出 JSON、导入、最近一次备份时间、导入前自动快照提示。

## 6. 内容模板系统

### 6.1 一条探索事件模板的 JSON 结构

```json
{
  "id": "evt_lighthouse_dusk_001",
  "version": 1,
  "type": "explore",
  "slots": {
    "location": "lighthouse",
    "mood": ["quiet", "tired"],
    "attribute": "mind",
    "season": ["autumn", "winter"],
    "outcome": ["small_gain", "insight"]
  },
  "title": "{地点}的{时段}",
  "body": "{开场}你在{地点}停下。{细节}。{收束}",
  "fragments": {
    "开场": ["风把门吹得轻响。", "灯还没亮。"],
    "细节": ["桌上有一本翻到一半的书", "窗外的海是铅灰色"],
    "收束": ["你坐了一会儿，什么也没做。", "你记下一句话，然后合上本子。"]
  },
  "rewards": { "xp": 12, "ember": 3, "attribute": { "mind": 1 } },
  "weight": 8,
  "cooldownDays": 14,
  "requires": { "minLevel": 2 },
  "excludes": ["evt_lighthouse_dusk_002"],
  "tags": ["solitude", "night", "no_dialogue"]
}
```

**字段说明**

- `slots`：五个维度（地点 5 × 情绪 4 × 属性 5 × 季节 4 × 结果 3），用于检索与组合，不直接拼进正文。
- `fragments`：真正用于渲染的句段库，按语义槽分组，每组 2–4 条。
- `rewards`：固定区间，按难度微调，**不允许随机大额**。
- `excludes`：互斥 id，避免同一晚出现两个「灯塔」。
- `tags`：供兼容性规则使用。

### 6.2 槽位与变体的组织方式

- 组合不是字符串随机拼接，而是「模板骨架 + 语义槽位」。每个槽位有 grammar 标记（名词/动词短语/形容词），只允许同标记互换。
- **兼容规则三层**：
  1. 语义互斥：tags 冲突（如 `indoor` 与 `outdoor`）不共存。
  2. 情绪匹配：事件 mood 必须包含用户当日心情，或为空（通用）。
  3. 句式去重：同一模板 14 天内只用一次；同一 fragments 组内的句子，7 天内不重复。
- **生成流程**：筛选候选 → 按 weight 加权 → 种子 PRNG（`playerId + localDate + eventId`）抽取 → 组装 → 二次校验（长度 40–120 字、无禁用词、无重复句）→ 失败则回退到通用池。
- **安全**：所有 fragments 预先人工审校；上线前跑一遍禁用词表（与 §2.4 同一份）。

## 7. 本地规则引擎（原「AI 辅助」）

### 7.1 定位

**不联网、不需要 API Key、不申请网络权限。**

原方案考虑过接入 AI，但三个约束同时成立时它不可行：无服务器（只能让用户自己填 Key）+ 免费（不能代付）+ 面向普通用户（他们不会去申请 Key）。

所以改为**本地规则引擎**：用模板、关键词匹配和统计规则，产出「像人写的」结果。效果上限低于真 AI，但对「不联网也完整可用」这条硬约束是唯一自洽的解法。

**不标注「AI 生成」**，因为它本来就不是。界面上直接叫功能名。

### 7.2 提供的两个功能

| 功能 | 输入 | 输出 | 本地实现 |
| --- | --- | --- | --- |
| **温柔复盘** | 最近 7 天记录 | 120 字以内总结：一个模式、一件值得保留的小事、一个下周可尝试的微调 | 24 条总结模板 × 12 个变量槽位（完成率区间、最稳习惯、最常时段、断签次数、属性分布…），按记录数/完成率/时段选模板 |
| **任务拆解** | 一件拖着没做的事 | 3 个可在 15 分钟内完成的第一步 | 动词库（准备/联系/打开/写下/清理/预约）× 任务名关键词匹配；识别失败时给通用兜底：「先花 2 分钟，把这件事需要的东西列出来」 |

### 7.3 明确不做

- 聊天伴侣、闲聊、情感陪伴对话
- 心理诊断、情绪分析结论
- 自动创建大量任务、自动修改数值
- 读取通讯录 / 相册 / 健康数据 / 位置
- 任何形式的网络请求

### 7.4 隐私说明（原文，放在设置页页底）

**阶段 1 用的版本**（备份与导出还没做，所以不提）：

> 这个 App 没有网络权限。没有账号，没有服务器，数据只在这台手机上。

**导出与删除上线后换成完整版**：

> Ember 没有任何网络权限。你的记录只存在这台手机上，不会发送到任何地方。这里没有任何 AI 服务，所有「复盘」「拆解」都是用内置模板生成的。你可以随时导出全部数据，也可以一键删除全部数据。

**「没有网络权限」必须在配置里坐实，不能只写在文案里。** Expo 的 Android manifest 模板默认带 `INTERNET`、`SYSTEM_ALERT_WINDOW`、`VIBRATE` 和读写外部存储权限（`@expo/config-plugins` 的 `withAndroidBaseMods.js`）。所以 `app.json` 的 `android.blockedPermissions` 必须显式移除 `INTERNET` 与 `ACCESS_NETWORK_STATE`——否则这句话就是假的，用户装完在系统设置里能查到联网权限。

## 8. 空状态与边界情况

零基础开发者最容易忽略、但用户最先撞上的地方。

| 场景 | 表现 |
| --- | --- |
| 首次打开，还没有任何任务 | 显示引导第 2 屏的模板卡片，**不是空白列表** |
| 今天所有习惯都完成了 | 问候换成「今天到这儿了。」，不推荐新任务 |
| 今天一个任务都没有 | 「今天空着。要不要放一件小事进来？」+ 3 个快捷模板 |
| 目标一个任务都没挂 | 显示「还没挂任务」，不显示「0 / 0」 |
| 目标的关联任务全做完了 | 那一行多一句「关联的事都做完了。这个目标算完成了吗？」，详情页给出「算完成了」——用户自己决定，不自动关闭 |
| 连胜为 0（从未开始） | 不显示连胜数字，显示「第一天」 |
| 断签后 | 显示「历史最佳 X 天 / 累计 Y 天」，**不显示「归零」** |
| 撤销一次打卡后 | 行回到空心、连胜按剩下的事实重算；数字可能变小，但不出现 0 与「归零」 |
| 读不到数据库 | 「今天的数据暂时读不出来。」+「再试一次」；**不说「今天空着」**——那是在骗人 |
| 一个目标都没有 | 「还没有目标。可以先在「今天」记几天，看看自己真正在意哪件事，再回来写一句。」+「写一句」；今天还有事没做时不提「去记几天」 |
| 可挂的任务一件都没有 | 「还没有可挂的事。先去「今天」加一件，再回来。」+ 一个跳转 |
| 连续 30 天没打开 | 打开时先给「回归小结」recap，不是直接进首页 |

## 9. 无障碍与细节

| 项 | 要求 |
| --- | --- |
| 触控目标 | 最小 44×44 |
| 对比度 | 正文文字对比度 ≥ 4.5:1（唯一一套色板已按此校验） |
| 字号缩放 | 跟随系统字号，最大不超过 1.5 倍（超过会破坏布局，需在代码里限制） |
| 减少动效 | `reduce_motion = 1` 时关闭呼吸、位移、缩放动画，只保留淡入淡出 |
| 深色模式 | v0.1 没有。app.json 的 `userInterfaceStyle` 固定为 `light`，系统切到深色时界面不变 |
| 色盲 | 状态不能只靠颜色区分，必须配合图标、形状或文字。已落实：底栏选中态同时改线宽（1.45→1.95）、明度与余烬点；完成态同时改字重与圆点填充（§4.2） |
| 触感反馈 | 打卡成功用轻触感；升级用中触感；可用设置关闭 |
